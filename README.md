## Этап 1. Минимальный прототип с конфигурацией

### Шаг 1. Чтение корректных настроек

Настройки хранятся в [config.json](config.json):

```json
{
  "package": "express",
  "repository": "https://registry.npmjs.org",
  "test_mode": false,
  "ascii_tree": false,
  "max_depth": 3
}
```

| Параметр | Значение и назначение |
| --- | --- |
| `package` | Имя анализируемого пакета; здесь `express` |
| `repository` | URL реестра npm; в тестовом режиме — путь к файлу |
| `test_mode` | `false` — реальный реестр; `true` — тестовый файл |
| `ascii_tree` | Настройка вывода ASCII-дерева; сам вывод относится к этапу 5 и здесь не реализуется |
| `max_depth` | Максимальная глубина анализа, целое число не меньше 0; корень имеет глубину 0 |

Запуск:

```powershell
python src/main.py --config config.json
```

![Корректное чтение пяти настроек](screenshots/01-config-success.png)

**Результат и объяснение:** программа прочитала JSON, проверила значения
и вывела все пять параметров в формате ключ-значение. `False` в выводе Python
соответствует `false` в JSON. Этот вывод — требование первого этапа;
анализ зависимостей пока не производится.

`--config` задаёт только путь к файлу; все пять пользовательских настроек
читаются из JSON. Без `--config` используется `config.json` в текущей папке.
Имя обычного пакета проверяется как имя npm, включая форму `@scope/name`.
В тестовом режиме допускаются имена из больших латинских букв.

### Шаг 2. Проверка отрицательной глубины

В `config.json` временно заменить значение на:

```json
"max_depth": -1
```

Сохранить файл и повторить команду запуска из шага 1.

![Ошибка отрицательной глубины](screenshots/02-error-max-depth.png)

**Результат:** программа сообщает, что требуется целое число не меньше 0.
Отрицательная глубина отклоняется. После проверки вернуть `"max_depth": 3`.

### Шаг 3. Проверка пустого имени пакета

Временно заменить значение:

```json
"package": ""
```

Сохранить файл и повторить запуск.

![Ошибка пустого имени пакета](screenshots/03-error-package.png)

**Результат:** программа требует непустое имя пакета.
После проверки вернуть `"package": "express"`.

### Шаг 4. Проверка неверного URL

При `"test_mode": false` временно указать:

```json
"repository": "wrong-address"
```

Сохранить файл и повторить запуск.

![Ошибка некорректного адреса репозитория](screenshots/04-error-repository.png)

**Результат:** программа требует URL с `http://` или `https://` и адресом сервера.
Это проверка формата URL, а не доступности сервера в интернете.
После проверки вернуть `"repository": "https://registry.npmjs.org"`.

### Шаг 5. Проверка типа test_mode

Временно указать значение в кавычках:

```json
"test_mode": "false"
```

Сохранить файл и повторить запуск.

![Ошибка типа параметра test_mode](screenshots/05-error-test-mode.png)

**Результат:** программа требует логическое значение `true` или `false`.
`"false"` в кавычках является строкой, поэтому оно отклоняется.
После проверки вернуть `"test_mode": false` без кавычек.

### Шаг 6. Проверка типа ascii_tree

Временно указать:

```json
"ascii_tree": "true"
```

Сохранить файл и повторить запуск.

![Ошибка типа параметра ascii_tree](screenshots/06-error-ascii-tree.png)

**Результат:** строка `"true"` не является логическим значением.
После проверки вернуть `"ascii_tree": false` без кавычек.
Таким образом, вручную продемонстрированы ошибки всех пяти параметров.

### Шаг 7. Настройки тестового режима

В [examples/test-config.json](examples/test-config.json) подготовлены
отдельные настройки:

```json
{
  "package": "A",
  "repository": "test-repository.json",
  "test_mode": true,
  "ascii_tree": false,
  "max_depth": 3
}
```

Запуск:

```powershell
python src/main.py --config examples/test-config.json
```

![Успешное чтение настроек тестового режима](screenshots/07-test-config-success.png)

**Результат:** выбран пакет `A` и тестовый файл вместо URL, режим `test_mode`
включён. Программа проверяет существование файла, но на этапе 1 ещё не анализирует
его граф. Относительный путь `repository` считается от папки конфигурационного
файла, поэтому здесь используется `examples/test-repository.json`.
Этот файл содержит подготовленный пример графа для этапа 3.

## Обработка ошибок

Ошибки конфигурации выводятся в терминал, приложение завершается с кодом 2.
Помимо проверок на скриншотах, программа обнаруживает отсутствующие и лишние
поля, повторяющиеся ключи, повреждённый JSON, отсутствие конфигурационного
файла и отсутствие файла тестового репозитория.

Проверка отсутствующего файла конфигурации:

```powershell
python src/main.py --config missing.json
```

После ручных проверок в основном `config.json` сохранены корректные значения
из шага 1. Не следует одновременно оставлять несколько ошибок:
программа сообщает первую обнаруженную причину.

## Связь с кодом

| Файл | Назначение |
| --- | --- |
| [src/main.py](src/main.py) | `main()` читает аргумент `--config`, вызывает загрузчик, выводит параметры и задаёт код завершения |
| [src/config.py](src/config.py) | `Settings` хранит настройки; `validate()` проверяет значения; `unique_keys()` запрещает повтор ключей; `load_settings()` читает JSON; `ConfigError` описывает ошибки |
| [tests/test_config.py](tests/test_config.py) | Шесть автоматических тестов с проверками разных входных данных |
| [examples/test-repository.json](examples/test-repository.json) | Пример графа тестового репозитория для будущего этапа 3 |
| [screenshots](screenshots) | Скриншоты фактических проверок первого этапа |

Последовательность работы: запуск `main.py` → чтение JSON в `load_settings()` →
проверка параметров в `validate()` → объект `Settings` → вывод ключ-значение.
При ошибке вместо вывода настроек показывается её причина.
