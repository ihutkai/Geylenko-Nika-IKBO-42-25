# Эмулятор оболочки — вариант 6

Учебный проект на Python и Tkinter. Реализованы только этапы 1–3:
REPL, конфигурация и загрузка JSON VFS в память.
Этапы 4 и 5 не входят в выбранный объём работы.

## Запуск

Нужен Python 3.11 или новее с Tkinter. Сторонние пакеты не требуются.
Из папки проекта:

```console
python src/main.py
```

В Windows также можно запустить `run.bat`. Проверка Tkinter:
`python -m tkinter`.

## Команды и настройки

- `ls [путь]`: заглушка, печатает своё имя и список аргументов.
- `cd [путь]`: заглушка, печатает своё имя и список аргументов.
- `exit`: закрывает приложение; аргументы запрещены.
- Пустой ввод не выполняет команд.
- Неизвестные команды и лишние аргументы выводят сообщение об ошибке.

Парсер использует `str.split()`: повторные пробелы игнорируются.
Кавычки, пути с пробелами, флаги и конвейеры пока не поддерживаются.
`ls` и `cd` принимают не более одного аргумента пути.
Заголовок содержит имя загружаемого JSON-файла VFS.

## Устройство

- `src/shell.py`: `CommandResult` хранит результат команды;
  `execute()` разбирает строку и выполняет команды.
- `src/main.py`: `ShellWindow` создаёт окно; `write()` добавляет вывод;
  `submit()` обрабатывает Enter; `main()` запускает цикл событий.
- `tests/test_shell.py`: автоматические проверки команд и ошибок.

## Проверка

```console
python -m unittest discover -s tests -v
```

Для интерактивной демонстрации введите по очереди:

```text
ls
ls /home
cd
cd /home/user
ls a b
cd a b
unknown
exit argument
exit
```

Также проверьте пустую строку и ввод `  ls   /home  `.
Последняя команда `exit` должна закрыть окно.

Каждый этап задания нужно сохранить отдельным коммитом в публичном
репозитории. Этот проект пока не опубликован.

## Этап 2: конфигурация и стартовый скрипт

Запускать следующие команды нужно в терминале из папки проекта:

```console
python src/main.py --config config.toml
python src/main.py --vfs examples/minimal.json --startup examples/startup.txt
python src/main.py --config config.toml --vfs examples/deep.json
```

`--config` задаёт TOML-файл с ключами `vfs_path` и `startup_script`.
`--vfs` и `--startup` переопределяют соответствующие значения TOML.
Без параметров загружается `examples/vfs.json`, стартовый скрипт не задан.
Файл конфигурации читается только при явном указании `--config`.
Все относительные пути считаются от текущей рабочей папки терминала.
Итоговые настройки выводятся в терминал и окно эмулятора.
На этапе 3 JSON загружается до выполнения стартового скрипта.

`load_settings()` в `src/config.py` разбирает аргументы и проверяет TOML;
при ошибке выводит сообщение в терминал и завершает запуск с кодом 2.
`run_startup()` в `src/startup.py` читает UTF-8 скрипт и показывает команды
и результаты в GUI. Пустые строки и комментарии после `#` пропускаются.
После ошибки команды выводится номер строки, выполнение продолжается.
При ошибке чтения скрипта окно остаётся доступным для ручного ввода.
Команда `exit` завершает скрипт и закрывает окно.

Демонстрации для Windows: `scripts/check_parameters.bat` и
`scripts/check_errors.bat`. Каждый файл проверяет все параметры запуска.
Закрывайте очередное окно, чтобы перейти к следующему примеру.
Примеры включают приоритет CLI, ошибки чтения и синтаксиса TOML,
отсутствующий скрипт, ошибки команд, комментарии и выход из скрипта.

## Этап 3: виртуальная файловая система

```console
python src/main.py --config config.toml --startup examples/stage3.txt
python src/main.py --vfs examples/deep.json --startup examples/stage3.txt
```

`src/vfs.py` содержит `VirtualFileSystem` — набор путей каталогов и словарь
файлов (путь → байты). `load_vfs()` читает JSON, `read_node()` проверяет
дерево, `decode_file()` декодирует содержимое, `unique_object()` запрещает
повторяющиеся ключи. Ошибки представлены классом `VFSError`.
Все данные после загрузки находятся в памяти. Источник открывается только
для чтения; файлы и каталоги из VFS не создаются на реальном диске.

Корневой узел — каталог. Пример структуры JSON:

```json
{
  "type": "directory",
  "children": {
    "hello.txt": {
      "type": "file", "encoding": "utf-8", "content": "Привет!"
    },
    "data.bin": {
      "type": "file", "encoding": "base64", "content": "AAECA/8="
    }
  }
}
```

Каталог содержит только `type` и `children` (объект дочерних узлов).
Файл содержит только `type`, `encoding` и `content` (строка).
Кодировка: `utf-8` для текста или `base64` для двоичных данных.
Имена не могут быть пустыми, равняться `.` или `..`, содержать разделители
пути или управляющие символы. Неизвестные типы, поля и кодировки запрещены.

При успешной загрузке GUI показывает все пути и размеры файлов в байтах.
Это отладочный вывод загрузчика, а не реализация команд этапа 4.
`ls` и `cd` по-прежнему печатают имя и аргументы: например, `cd /missing`
не проверяет существование пути. В случае ошибки VFS окно показывает причину,
ввод отключается и стартовый скрипт не запускается. Закройте окно и исправьте
путь или формат перед повторным запуском.

Примеры VFS: `minimal.json` — пустой корень; `vfs.json` — текст, двоичный
файл и каталог; `deep.json` — несколько файлов на уровнях 1–4.
Два Windows-скрипта `scripts/check_vfs.bat` и
`scripts/check_vfs_errors.bat` проверяют все три структуры. Второй также
показывает ошибки отсутствующего файла, синтаксиса JSON, структуры и base64.
Окна закрываются вручную между запусками.

`examples/stage3.txt` демонстрирует все режимы заглушек `ls` и `cd`,
виртуальные пути, повторные пробелы и ошибки. `examples/exit.txt` проверяет
автоматический выход. Пустую строку проверьте вручную клавишей Enter.
Тесты проверяют приоритет настроек, команды, скрипты, двоичные данные,
вложенность VFS, повреждённые входные данные и неизменность исходного JSON.
